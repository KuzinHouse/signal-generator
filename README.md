# 🎛️ Signal Generator

Промышленный генератор сигналов с **мультиброкерной** публикацией в MQTT и веб-интерфейсом.

## Возможности

- Генерация сигналов: Sine, Sawtooth, Square, Noise, Random, Constant + **Triangle, Pulse, Ramp, RandomWalk, DoubleSine** + эффекты (дрейф, шум, выбросы, мёртвая зона, гистерезис, залипание, джиттер, тренд, фаза, duty cycle, потеря пакетов, деградация качества)
- **Пределы измерения и пороги тревог** в каждом сигнале: мин/макс измерения + пороги предупреждения (warn) и аварии (alarm). Панель подсвечивается и попадает в счётчик тревог статус-бара
- **Параметры волны**: фазовый сдвиг (°), duty cycle (0..1), шаг случайного блуждания (walk sigma), период хода (ramp), вторая частота (биения)
- **Мультиброкерная публикация (v0.2.0)**: каждый сигнал публикуется **ПАРАЛЛЕЛЬНО** во все включённые MQTT-брокеры, каждый — на своём префиксе топиков. Список брокеров, их состояние и параллельность — на отдельной странице **`/brokers`**
- Публикация в MQTT (rumqttc) с авто-реконнектом на каждый брокер отдельно
- **Настраиваемые MQTT брокеры**: хост, порт, пользователь/пароль, префикс топиков, топик диагностики, TLS, вкл/выкл — через страницу `/brokers` или API
- **Персистентность настроек**: конфиг брокеров (`config/mqtt.json`) и генераторов (`config/generators.json`) сохраняются и переживают перезагрузку
- Формат payload: плоский JSON-LD-массив (`@id`, `@type`, `name`, `value`) либо **`records`** — массив записей платформы BlueTraktor/УСЕПИ (поле `payloadFormat`, по умолчанию `flat`)
- Топики: `{префикс}/{id}` / `{префикс}/{catalog}/{id}` (по умолчанию `USEPI/...`) + топик диагностики
- **Топик отображается на каждой панели генератора** — видно, куда публикуется сигнал
- REST API (actix-web): CRUD генераторов, toggle, текущее значение, **история сигналов**, CRUD брокеров, тест подключения, живой статус брокеров
- Веб-интерфейс без inline JS: SSR-панели, делегирование событий, canvas-графики (осциллограф на всю ширину + график нагрузки брокера)
- **Real-time через WebSocket**: дифф-снапшоты каждые 500 мс (только изменённые сигналы), полный раз в 5 с
- **Поиск/фильтр генераторов** по имени, id, топику + фильтр по типу волны
- **Счётчик тревог** (alarm/warning) в статус-баре — оператор сразу видит проблему
- **MQTT Last Will** — при падении процесса каждый брокер публикует offline-статус в свой топик диагностики
- **Серверная история сигналов** — осциллограф сразу показывает прошлые данные при выборе канала
- **Favicon + версия приложения** в статус-баре
- **Опциональная авторизация API** (SIGNAL_API_TOKEN, Bearer для мутаций + защита WebSocket через ?token)
- **Экспорт/импорт конфигурации** — полный бэкап (генераторы + ВСЕ брокеры) одним JSON-файлом
- **TLS для MQTT** (use_tls в настройках брокера)
- Docker healthcheck
- Docker + docker-compose для деплоя

## Быстрый старт

```bash
cargo run --release
# Веб-интерфейс: http://localhost:8080
# Настройки брокеров: http://localhost:8080/brokers
# API: http://localhost:8080/api/generators
```

## Настройка MQTT (мультиброкер)

Отдельная страница **`http://localhost:8080/brokers`** — полный CRUD брокеров. Каждый брокер:

| Поле | Описание |
|------|----------|
| Название | Человекочитаемое имя для карточки |
| ID (фраза) | Уникальный идентификатор брокера (local, remote…) |
| Хост | Адрес брокера (IP или hostname) |
| Порт | Порт брокера (по умолчанию 1883) |
| Префикс топиков | Шаблон `{префикс}/{id}` для сигналов генераторов |
| Топик диагностики | Куда публикуется диагностика каждые 10 сек + LWT offline |
| Пользователь / Пароль | Опциональная авторизация |
| TLS | Шифрование соединения (порт 8883, системные корни) |
| Включён | Публиковать ли сигналы в этот брокер |

Каждый **включённый** брокер получает КОПИЮ каждого сигнала на своём префиксе топиков, публикация идёт параллельно. Кнопка «ПРОВЕРИТЬ» выполняет TCP-тест соединения.

Список брокеров сохраняется в `config/mqtt.json` (атомарно) и переживает перезагрузку. При изменении брокера (вкл/выкл/правка) соединение пересоздаётся без рестарта процесса. Импорт поддерживает и старый одиночный, и новый мультиброкерный формат.

Дефолтные брокеры:
- `local` → `127.0.0.1:1883` (локальный EMQX)
- `remote` → `79.174.94.236:1883` (внешний брокер)

### API

```bash
# История сигнала (для осциллографа)
curl 'http://localhost:8080/api/generators/temp-01/history?limit=120'

# Список брокеров (пароли маскируются)
curl http://localhost:8080/api/brokers

# Живой статус всех брокеров
curl http://localhost:8080/api/brokers/status

# Добавить брокер
curl -X POST http://localhost:8080/api/brokers \
  -H "Content-Type: application/json" \
  -d '{"id":"backup","name":"Фолбэк","host":"10.0.0.5","port":1883,"topic_prefix":"USEPI","diagnostics_topic":"USEPI/diagnostics","enabled":true,"use_tls":false}'

# Включить/выключить брокер
curl -X PUT http://localhost:8080/api/brokers/backup/toggle

# Удалить брокер
curl -X DELETE http://localhost:8080/api/brokers/backup

# Тест соединения (TCP) с указанным брокером
curl -X POST http://localhost:8080/api/mqtt/test \
  -H "Content-Type: application/json" \
  -d '{"host":"79.174.94.236","port":1883}'

# Бэкап всей конфигурации (генераторы + ВСЕ брокеры)
curl http://localhost:8080/api/config/export > backup.json

# Восстановить из бэкапа
curl -X POST http://localhost:8080/api/config/import \
  -H "Content-Type: application/json" \
  -d @backup.json

# Обновить список брокеров целиком
curl -X PUT http://localhost:8080/api/mqtt/config \
  -H "Content-Type: application/json" \
  -d '{"brokers":[{...},{...}]}'
```

## Форматы payload (BlueTraktor/УСЕПИ)

Каждый генератор имеет поле **`payloadFormat`**:

| Значение | Поведение |
|----------|-----------|
| `flat` *(по умолчанию)* | Текущий плоский JSON-LD-массив записей генератора (`timestamp`, `response_code`, значение, `*_unit/_min/_max/_warn_*/_alarm_*/_status/_quality`, для Modbus — ещё `*_modbus_*`). Обратная совместимость: старые `config/generators.json` без поля читаются как `flat`. |
| `records` | Массив записей промышленной платформы BlueTraktor (УСЕПИ). |

В режиме `records` по топику генератора публикуется массив **фиксированного вида**.
Идентичность записи — её `@id` (а не позиция в массиве). Запись значения имеет
`@id = последний сегмент топика`; записи-спутники — `<id>_unit`, `<id>_min`,
`<id>_max`. Порядок: `timestamp`, `<id>`, `<id>_unit`, `<id>_min`, `<id>_max`, `quality`.

Числовые значения округляются до **не более 4 знаков** после запятой. Для дискретных
(`Constant`, `Square` и т.п.) и строковых сигналов формат тот же.

Пример (генератор `press-01`, каталог `pressure`, префикс брокера `USEPI`,
топик `USEPI/pressure/press-01`, формат `records`):

```bash
mosquitto_sub -h localhost -t 'USEPI/pressure/press-01' -v
```

```json
[
  {"@id":"timestamp","@type":"value","name":"Временная метка","value":"2026-10-12T18:13:47.211Z"},
  {"@id":"press-01","@type":"value","name":"Давление #1","value":0.4235},
  {"@id":"press-01_unit","@type":"value","name":"Единица измерения","value":"bar"},
  {"@id":"press-01_min","@type":"value","name":"Мин измерения","value":-7.5},
  {"@id":"press-01_max","@type":"value","name":"Макс измерения","value":50.0},
  {"@id":"quality","@type":"value","name":"Качество данных","value":98}
]
```

Включить формат `records` можно в конфиге генератора:

```json
{
  "id": "press-01",
  "catalog": "pressure",
  "payloadFormat": "records",
  "waveType": "Noise"
}
```

Мультиброкерная публикация не меняется: каждый включённый брокер получает ту же
последовательность топиков, payload одинаковый (последний сегмент топика у всех
брокеров совпадает = `id` генератора).
